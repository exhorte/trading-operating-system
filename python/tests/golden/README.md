# Golden vectors

`analysis.json`, `s01.json` and `numbers.json` are the **oracle** the Python ports are held to. They were generated by running the
TypeScript originals (`lib/analysis`, `lib/setup`) — and Node's own number formatting for `numbers.json` — on deterministic,
seeded inputs (a `mulberry32` generator), then written down: the inputs *and* the outputs. The Python tests replay the inputs
and demand **exact equality** with the outputs (`tests/unit/domain/analysis/test_golden.py`,
`tests/unit/domain/s01/test_golden.py`, `tests/unit/test_numbers.py`).

The TypeScript originals were removed from the working tree when the cockpit stopped carrying the domain (phase 6–7 of the
Python-native migration). They, and the generators that drove them, remain in git history:

| What | Where it lives |
|---|---|
| `lib/analysis/`, `lib/setup/`, `lib/domain/` (the originals) | the tree at commit `dc8db3e` (`feat(python): types TypeScript du cockpit …`) and before |
| `python/tests/golden/generate_analysis_vectors.ts`, `generate_s01_vectors.ts`, `support.ts`, `generate_number_vectors.mjs` | the same commit |

To regenerate a vector set (which only makes sense if the *original* behaviour is being re-examined, never to make a failing
Python test pass): check that commit out in a scratch worktree, `npm ci`, and run the generator with `npx tsx` (or `node` for the
`.mjs`), redirecting its output over the matching JSON file. A vector file that changes is a change of the oracle and needs a
human decision, not a green test.
